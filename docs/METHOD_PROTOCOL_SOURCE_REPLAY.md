# Replay the frozen method and report sources

This publication contains the fixed method adapters, execution protocols and
report gates, with archive-backed preparation and historical recovery evidence.
It packages existing bytes after execution began. The original scientific
configurations, freezes, fourteen implementations and 59 current source-map
entries remain unchanged. It reports no docking accuracy or method advantage.

Run the source-only checks with the repository's pinned Python dependencies:

```sh
python scripts/verify_method_protocol_sources.py
python -m pytest -q tests/test_method_protocol_sources.py
```

The verifier copies an explicit list of public file pins into a private
temporary directory and verifies 2,239 archive members. It checks source hashes
and input correspondence without importing a report reader, executing an
installed program, predicting a site, scoring a pose or computing accuracy.
Temporary files are removed when verification finishes.

| Archive group | Verified regular files | Scope |
| --- | ---: | --- |
| Preparation foundation | 698 | Main and assembly-control source conditions, boxes, failure records and predictor input streams |
| HADDOCK prepared inputs | 215 | 214 source/preflight files and their embedded original manifest |
| HADDOCK topology preflight | 550 | 549 saved source/topology files and their embedded original manifest |
| Recovered first job | 240 | One complete historical native run, including its original driver-failure evidence |
| Recovery metadata | 11 | Ten historical metadata/source files and their embedded original manifest |
| Development inputs | 525 | Exact old156 and corrected9 input bundles, source snapshots and preparation metadata |

The four new hydration manifests in
`results/method_protocol_source_distribution/` cover every member of the
unchanged HADDOCK archives. Each binds its original frozen manifest. They make
archive prefixes and self-embedded manifests explicit; they do not amend the
original numerical data or receipts. The development bundle separately records
post-start packaging and retains both compressed and uncompressed input hashes.
No live native progress or additional native outcome trees are included.

`benchmarks/method_protocol_public_distribution.json` defines exact file pins,
archive groups, fourteen implementation hashes, the 59 source-map entries and
twelve historical receptor aliases. Its hash is bound by the packaging helper.
The generic `replay_workspace` hydrator verifies regular member identities,
sizes, hashes, collisions and safe paths before publication into the private
fixture. It never reads an ignored live input tree.

The historical topology tests need twelve `data/processed/.../receptor.pdb`
names. A separate narrow helper creates only those names inside a verified
private temporary fixture, using exact bytes from the pinned public strict and
repair source archives. It rejects Git/bare-repository roots, changed pins and
symlink paths. The generic hydrator continues to reject processed-tree targets.
The four metric-reader pending demonstrations require neither a processed tree
nor installed tools.

The public tests preserve all numerical, saved-topology, source, lineage and
corruption controls. Three full CNS/release/runtime installation checks remain
explicitly optional local checks under `AAV_LOCAL_NATIVE_VALIDATION=1`.
Historical installation metadata does not claim that a local installation was
reverified. Adapted test hashes and their unchanged historical archive copies
are recorded in the publication amendment; old receipts retain their old pins.

The global gate retains the main216, HADDOCK108, assembly72 and exact-union
completion requirements. These denominators overlap. Pending public fixtures
block reference-context/metric entrypoints and return only workflow readiness.
Source verification never invokes global `--generate`. Complete scientific
report replay additionally requires every declared terminal output, failure
receipt, raw artifact and fixed-score record, plus the separate authorized
global release. Those output archives and reports are published separately.

Old156 and corrected9 preparation data are separate from the 698-file heldout
foundation. Corrected9 verifies receptor coverage, retained preparation and an
executed raw-output sensitivity. AAV has no qualified atomic reference here;
this fixture supports no atomic-recovery or pose/energy causal claim. The
qualified 3ZWE/5HZA assembly controls provide the separate H4 assembly estimates.
Corrected verification retains its historical code snapshot instead of
rewriting its pins to match the current package.
